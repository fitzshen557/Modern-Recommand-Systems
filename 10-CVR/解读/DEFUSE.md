# DEFUSE — Asymptotically Unbiased Estimation for Delayed Feedback Modeling via Label Correction

> 阿里妈妈（淘宝搜索广告） | WWW 2022 | 重要性采样路线的理论修正

---

## 一、背景与动机

DEFUSE 是对整条重要性采样方法路线（FNW/FNC → ES-DFM → DEFER）的一次系统性理论审视。淘宝搜索广告团队指出，这些方法在推导重要性权重时，都隐含了一个**未被验证的假设**：

```
真实分布 p(x,y) 与观测分布 q(x,y) 之间，
只存在概率密度在每个点 <x,y> 上的变化，
不存在 <x,y> 在取值空间上的变化。
```

翻译成人话：以往方法认为"同一个样本 x，只是真实分布和观测分布给它的概率权重不一样"，但**样本回补机制里，label 本身是会变的**（假负样本 FN 变成延迟正样本 DP 时，label 从 0 变成了 1）。这是一个 **取值空间的变化**，不是单纯的概率密度重新加权，以往方法把这两件事混为一谈了。

---

## 二、方法详解

### 2.1 回顾三种回补机制的差异

DEFUSE 论文对比了此前三类方法的回补策略：

```
FNC/FNW:  等待窗口=0，所有样本一开始都是负样本
          → 后续转化的样本回补为正样本

ES-DFM:   等待窗口>0
          → 只对"窗口外才转正"的样本做回补（只回补 FN→DP）

DEFER:    等待窗口>0，处理和 ES-DFM 类似
          → 但归因周期结束后，所有样本以真实label重新下发一次
            （不止回补FN，也重复处理RN，保证特征分布对称）
```

三种方法都在做"样本回补 + 重新加权"，但 DEFUSE 认为它们在**理论推导的严谨性**上有共同缺陷。

### 2.2 DEFUSE 的核心修正：用 y(v,d) 显式区分真实label和观测label

DEFUSE 引入更精确的符号：

```
y      : 真实label（样本最终的真实转化情况）
v      : 观测label（当前观测窗口下看到的转化情况）
y(v,d) : 真实label是观测label v 和延迟时间 d 的函数
```

把损失函数改写为：

```
Loss = E_p[ log f_θ(y|x) ]
     = E_q[ w(x,y) · log f_θ(y(v,d)|x) ]

其中 w(x,y) = p(x, y(v,d)) / q(x,v)
```

**关键区别（对比 DEFER）：**
1. DEFUSE **不假设** 观测特征分布=真实特征分布（即不要求 p(x)=q(x)），不需要像 DEFER 一样靠"全员重复处理"来强制凑出这个假设
2. 显式承认 `y = y(v,d)` 这个 label 本身依赖观测状态和延迟时间的事实

### 2.3 四类样本的划分

由于观测label v 和真实label y 都是离散变量，可以把样本严格划分为四类：

```
IP (Immediate Positive)  : 窗口内直接观测到转化       — 可直接观测
DP (Delayed Positive)    : 窗口外才转化（假负样本转正）  — 可直接观测（回补后已知）
RN (Real Negative)       : 真的不会转化                — 无法直接与FN区分
FN (Fake Negative)       : 窗口内暂未转化，但其实会延迟转化 — 无法直接与RN区分
```

**核心难点：RN 和 FN 在观测窗口内表现完全一样（都是"暂时没转化"），无法直接区分。**

### 2.4 引入隐变量 z 解决 RN/FN 区分问题

DEFUSE 引入隐变量 `z` 表示"一个观测到的负样本实际是假负样本FN的概率"：

```
z = p_DP / (p_RN + p_DP)
```

`z` 有两种求解方式：

**方式一（推荐，效果更好）：**
```
z1(x) = 1 - f_rn(x)

需要单独训练一个二分类模型 f_rn(x)，
预测"一个观测到的负样本，实际是真负样本"的概率

优点：形式简单，实践效果通常更优
```

**方式二（理论完整但不稳定）：**
```
z2(x) = f_dp(x) / (1 - f_θ(x) + f_dp(x))

用已训练的无偏CVR模型 f_θ(x) 和延迟模型 f_dp(x) 直接计算，
不需要引入额外模型

缺点：形式复杂，预估方差大，稳定性差
```

### 2.5 四类样本的重要性权重简化

考虑到 DP（延迟正样本）是可直接观测的，DEFUSE 做了简化约束：

```
w_DP(x) = 1          # DP样本权重直接设为1（因为可观测，无需纠偏）
w_FN(x) = f_dp(x)     # FN样本权重用延迟概率模型输出
```

结合隐变量 z 的建模，最终得到一个理论上渐近无偏（asymptotically unbiased）的 CVR 估计。

## 三、Bi-DEFUSE：解决实践中的高方差问题

DEFUSE 虽然理论上更严谨，但论文作者在实际落地时发现：**对隐变量 z 的预估存在较大方差**，导致训练收敛变慢或陷入次优解。

**观察到的业务特点：** 实际场景中大约一半的成交会在很短时间内完成（比如淘宝搜索广告场景里，30分钟内完成的转化占比很高）。

**Bi-DEFUSE 的改进：拆分成两个子任务分别建模**

```
子任务1 — 窗口内成交 F_IP(x)：
  观测分布与真实分布完全一致（因为是直接观测到的）
  直接用标准二分类建模即可，不需要重要性权重纠偏

子任务2 — 窗口外成交 F_DP(x)：
  观测分布类似 FNW 的回补机制
  需要按照 ES-DFM 风格的重要性权重推导来处理

最终 CVR 输出 = F_IP(x) + F_DP(x)
```

这个拆分的核心价值：**把"确定性好建模"的部分（窗口内成交）和"不确定性强"的部分（窗口外成交）分开处理**，避免用一套复杂的隐变量估计去"污染"本来很简单就能建模好的那部分样本。两个子任务通过多任务学习框架联合训练。

## 四、实验结果

论文在淘宝搜索广告的真实业务数据上做了详尽的离线实验，核心结论：
- DEFUSE/Bi-DEFUSE 相比 ES-DFM、DEFER 等业界主流方案，在无偏性验证指标上取得更稳定的收益
- 在阿里妈妈搜索广告主场景取得了显著的在线效果提升（具体数值未在公开渠道详细披露，属于内部业务指标）
- Bi-DEFUSE 相比 DEFUSE，训练收敛速度和稳定性有明显改善，验证了"拆分建模降低方差"的有效性

## 五、懂哥点评

**核心贡献：这是延迟反馈领域少见的"理论修正型"工作。** 它没有提出全新的架构，而是回头审视了整条方法路线（FNW→ES-DFM→DEFER）共同的理论假设漏洞——把"label取值空间的变化"错误地当成了"概率密度的变化"。这种从第一性原理出发去审视既有方法论的能力，比单纯堆砌新模块的工作更有含金量。

**RN/FN 区分问题的意义：** 这本质上是延迟反馈问题里最核心的不确定性来源——**你永远不知道一个"暂未转化"的样本是真的不会转化，还是会晚点转化**。DEFUSE 用隐变量 z 显式建模这种不确定性，而不是像早期方法一样简单假设一个固定等待窗口，这是方法论上的进步。

**Bi-DEFUSE 的工程智慧：** "把确定的部分和不确定的部分分开建模"是一个非常通用的工程原则，不止适用于CVR延迟反馈——遇到复杂的隐变量估计问题，先看看是否可以拆分出一部分不需要隐变量估计的"简单子问题"，往往能大幅降低系统复杂度和训练不稳定性。

**局限性：**
1. z1(x) 和 z2(x) 两种估计方式的选择本身需要业务经验判断，论文虽然推荐 z1 但没有给出严格的理论依据说明何时该用哪种
2. 隐变量估计天然带来额外的模型训练和维护成本（f_rn(x) 或 f_dp(x) 都需要单独训练和调优）
3. Bi-DEFUSE 的"窗口内/窗口外"拆分本质上依赖对业务转化时间分布的先验判断（比如"30分钟"这个阈值），换到延迟分布特征差异很大的其他业务场景，可能需要重新调整拆分策略

**对你天级归因体系的启发：**

1. **"确定性部分和不确定性部分分开建模"的思路完全可以复用**：你的天级归因体系里，"当天转化"（确定性高）和"归因窗口内但非当天转化"（不确定性来源，涉及是否会被截断）可以拆开建模，参考 Bi-DEFUSE 的两塔设计
2. **隐变量视角**：被归因窗口截断的样本，本质上也是一个 RN vs FN 的区分问题——"真的不会转化" vs "会在窗口外转化但被你的系统当成负样本"，DEFUSE 的隐变量建模思路（用一个辅助分类器预测"这条负样本实际上是延迟转化"的概率）可以直接迁移过来做样本降权
