# DEFER — Real Negatives Matter: Continuous Training with Real Negatives for Delayed Feedback Modeling

> 阿里妈妈 | KDD 2021 | 重要性采样路线的集大成之作

---

## 一、背景与动机

在 DEFER 之前，业界已经有一批基于重要性采样（Importance Sampling, IS）的延迟反馈方法：FNW/FNC（Twitter, RecSys 2019）、ES-DFM（阿里, AAAI 2021）。这些方法的核心思路都是：

```
先让样本以"假负样本"的身份进模型训练（保证时效性）
等真正转化发生后，把这个样本以正样本的身份"回补"进模型（保证正确性）
用重要性权重纠正观测分布和真实分布之间的偏差
```

但阿里妈妈团队发现 ES-DFM 存在一个隐藏问题：**只对"假负样本转正"这一种情况做回补，没有对应处理"真负样本"（Real Negative）**，这导致重要性采样理论的基本假设 `p(x) = q(x)`（观测特征分布=真实特征分布）不再成立——因为假负样本被回补入模型两次，而真负样本只入模型一次，特征空间的分布结构被破坏了。

**DEFER 的核心洞察就是标题所说的："Real Negatives Matter"（真负样本也很重要）。**

---

## 二、方法详解

### 2.1 ES-DFM 的问题回顾

先复习一下 ES-DFM 的回补机制（这是理解 DEFER 改进点的前提）：

```
等待窗口 w > 0

样本分为三类：
1. 观测时已转化（Positive, Pos）
2. 观测时未转化，但后来转化了（假负样本转正，Delayed Positive）
3. 观测时未转化，且一直没转化（真负样本，Real Negative）

ES-DFM 的处理：
  假负样本 → 先以负样本身份入模型一次，转正后再以正样本身份入模型一次（入模型2次）
  真负样本 → 只入模型一次
  正样本   → 只入模型一次

问题：入模型总样本集合中，假负样本被"重复计数"，
      导致观测的特征分布 ≠ 真实的特征分布
```

### 2.2 DEFER 的核心改进：所有样本都处理两次

DEFER 的做法很直接——**既然假负样本要入两次，那真负样本也要入两次，保持对称性**：

```
DEFER 处理：
  假负样本（Fake_Neg）  → 入模型2次（先负后正）
  真负样本（Real_Neg）  → 入模型2次（重复处理，保持p(x)=q(x)）
  正样本（Pos）         → 入模型2次（重复处理，保持一致性）

观测到的负样本 = Real_Neg + Fake_Neg + Duplicate_Neg = 2×Real_Neg + Fake_Neg
观测到的正样本 = Pos + Duplicated_Pos = 2×Pos + Fake_Neg
```

这个"全员重复处理"的设计保证了观测特征分布和真实特征分布严格一致，重要性采样理论的前提假设不再被破坏。

### 2.3 重要性权重推导

设 `z` 为转化延迟时间，`w1` 为等待窗口，观测分布中负样本的概率：

```
q(x, y=0) = p(x, y=0) + (1/2) · p(x, y=1, z>w1)
```

展开得到：

```
q(y=0|x) = p(y=0|x) + (1/2) · p_dp(x)

其中 p_dp(x) 表示"延迟正样本"（假负样本最终转正）的概率
```

对应的重要性权重：

```
w(y=0) = p(y=0|x) / q(y=0|x) = p(y=0|x) / [p(y=0|x) + 0.5·p_dp(x)]
w(y=1) = p(y=1|x) / q(y=1|x) = p(y=1|x) / [p(y=1|x) - 0.5·p_dp(x)]
```

### 2.4 最终损失函数

用转化率模型输出 `f_θ(x)` 替代 `p(y=1|x)`，单独训练一个辅助分类器拟合 `p_dp(x)`（假负样本转正的概率）：

```python
# 伪代码表示
def defer_loss(y_i, f_theta_xi, p_dp_xi):
    if y_i == 1:
        weight = f_theta_xi / (f_theta_xi - 0.5 * p_dp_xi)
        loss = -weight * log(f_theta_xi)
    else:
        weight = (1 - f_theta_xi) / (1 - f_theta_xi + 0.5 * p_dp_xi)
        loss = -weight * log(1 - f_theta_xi)
    return loss
```

### 2.5 Offline DEFER：离线场景的多塔设计

除了流式在线学习，DEFER 论文还给出了离线训练场景的解法——**按不同等待时间分桶，用多个预测塔分别建模**：

```
共享底层 Embedding
    │
    ├─→ 塔1：预测"是否在等待时间w1内转化"    p(z<w1, y=1|x)
    ├─→ 塔2：预测"是否在等待时间w2内转化"    p(z<w2, y=1|x)
    ├─→ 塔3：预测"是否在等待时间w3内转化"    p(z<w3, y=1|x)
    └─→ 最终塔：预测"是否最终转化"          p(y=1|x)

关键约束：
  样本的实际等待时间 < 某个塔对应的窗口时，该塔的梯度冻结不更新
  （因为此时还不能确定该样本在这个窗口内的真实标签）
```

举例说明：假设归因窗口是7天，设置4个塔分别对应等待时间1天/3天/5天/最终转化。一个"4天前点击"的样本：
- 可以用于训练塔1（1天窗口，已确定）
- 可以用于训练塔2（3天窗口，已确定）
- **不能**用于训练塔3（5天窗口，因为样本目前只等了4天，还不确定5天时的标签）
- 可以用于训练最终转化塔

这个多塔+分窗口冻结梯度的设计，本质上是**天级归因体系天然适配的架构**，值得重点关注。

## 三、实验结果

DEFER 在阿里妈妈内部展示广告数据集上验证：
- 相比 ES-DFM，特征分布一致性（p(x)=q(x) 的满足程度）显著提升
- 相比 FNW/FSIW，在保持时效性的同时降低了 CVR 预估偏差
- 在线 A/B 测试证明了收入指标的正向提升（具体数值未在公开渠道详细披露）

## 四、懂哥点评

**核心价值：** DEFER 解决的是重要性采样方法论层面的一个理论漏洞——"只回补正样本、不回补负样本"导致的分布失配。这个洞察很有价值：**任何做样本回补/重新加权的系统，都要检查回补机制是否破坏了整体的分布一致性假设**，这是一个通用的方法论提醒，不局限于CVR场景。

**代价：** 训练样本总量翻倍（所有样本都处理两次），带来明显的训练成本增加。这是一个经典的"正确性 vs 效率"的权衡——DEFER 选择了正确性优先。

**跟 DEFUSE 的关系（预告）：** DEFER 虽然解决了 p(x)=q(x) 的问题，但阿里妈妈后续的 DEFUSE 论文（WWW 2022）指出 DEFER 仍然隐藏了一个更深层的理论问题——把"假负样本回补时的label变化"当成了纯粹的概率密度变化，而忽略了 label 本身的取值空间变化。这个问题的解法见 DEFUSE 解读文档。

**对你天级归因体系的直接借鉴价值：**

1. **Offline DEFER 的多塔分窗口设计几乎是为天级归因体系量身定制的**——你可以直接参考这个思路，把"1天转化率"、"3天转化率"、"7天转化率"、"最终转化率"设计成共享底层的多个预测头，用样本实际等待时长动态决定哪些塔可以拿这条样本训练
2. 梯度冻结这个细节很重要，容易被忽略——用一条只等了4天的样本去训练"7天窗口"的塔，标签本身就是错的，必须屏蔽这部分梯度

**局限性：** 样本量翻倍在超大规模系统里是真实的工程成本，如果你的系统本身训练资源紧张，需要评估这个开销是否值得。相对轻量的替代方案是只对"高价值样本"（比如高客单价、高置信度延迟转化）做双重处理。
